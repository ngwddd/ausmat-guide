# 升学自检 · Advising self-check

规则驱动的升学建议生成器。填一份学生情况，工具把适用的建议汇总成一篇报告，
每段都标出它来自哪条规则。

页面本身是中英成对的，和站内其他页面一样：

| | 中文 | English |
| --- | --- | --- |
| | `index.html` | `en.html` |

语言是**构建期维度**，由根元素的 `data-lang` 决定。切换是页头右上角的普通链接，
**不需要 JavaScript**；站点样式表据此显示对应的文案。

这里曾经还有第二个维度：**已注册 / 非注册**两种模式，连同 `guest.html`、
`en-guest.html` 两张页。它被删掉了，原因是那个区分**不产生任何不同的建议**——
两种模式给出的规则完全相同，差别只是非注册学生少填几个看不懂的学籍字段。
代价却是每个改动都要在四份外壳里同步，而收益只是一种想象中的精确。
现在两个地址（`guest.html`、`en-guest.html`）返回 404；构建时会主动删掉
磁盘上的旧副本，套件也会检查这两个文件不再存在。

## 文件构成

| 文件 | 作用 |
| --- | --- |
| `notes/advising/*.html` | 两个静态外壳（中 / 英），表单、页签与表头都在标记里 |
| `notes/advising/courses.js` | **课程库**：56 条课程事实（院校、专业、已公布最低分、短要求行、链接），每条带本项目的链接实测状态 |
| `notes/advising/advising-rules.js` | **规则库**：类别、词表、阈值、能力表、30 条规则、矩阵、换算参数，中英双语。其中 2 条标为 `enabled: false`（见"停用的规则"） |
| `assets/advising.js` | 引擎：表达式求值、校验、报告拼装、界面行为 |
| `assets/advising.css` | 仅本工具使用的样式，配色全部继承站点的变量 |

配色不在本工具里定义。改 `assets/style.css` 的 `:root` 变量即可换整站配色，
本工具不需要跟着改——唯一的例外是打印样式，那里刻意固定为白纸黑字。

## 一个决定性的架构选择

**建议是数据，引擎里一条建议都没有。**

所有话术都在 `advising-rules.js` 里，每条规则带一个条件。引擎遍历规则库、
对每条规则求值、把命中的建议按类别顺序拼成报告。于是：

- 改建议永远不用碰引擎代码
- 加一条规则＝在数组里加一项
- 全部规则能在一处读完，而不是散在几百个公式里
- 每条规则带 `source` 和 `verified`，未核实的表述**显示为未核实**，而不是与已核实的外观一样

**规则总览**页签就是这件事的回报：它列出每一条规则、是否命中、内容是否已核实。
当建议埋在公式里时，这个视图根本无法存在，因为没有可供渲染的清单。

## 规则语言

规则条件是一个**小程序语言**的表达式，**不是 JavaScript**。引擎里没有任何
`eval`，也没有 `new Function`。这是刻意的：用 `Function` 编译的表达式能够触达
整个全局作用域，包括 `record.constructor.constructor("...")()`，而文本扫描堵不住
这个洞——逃逸发生在语言运行时里，不在扫描器看得见的名字上。解析表达式、解释语法树，
是把问题**消除**而不是缓解。

由此带来的约束：

- 没有箭头函数、语句、赋值、循环、函数定义
- 针对列表元素的比较走助手函数，因为这门语言表达不了回调：

```js
anyInterest("i.country", "Australia")                  // 任一意向国家
anyInterest("i.field", ["Medicine", "Dentistry"])      // 命中多个之一
!anyInterest("i.country", ["Australia", "United Kingdom"])
anyScoreBelow(T.weakMark)                              // 用命名阈值
record.estimatedAtar < record.targetAtar - T.targetGapPoints
```

- 只有固定的一批标识符可解析：`record`、`T`、以及助手 `anyInterest`、
  `countSubject`、`anyScoreBelow`、`anyValueBelow`、`hasSubject`、`score`、
  `anyInterestExpectationGap`、`anyInterestOptionalGap`、`anyInterestMissing`、
  `belowStatedMinimum`。**拼错会变成一条点名该规则的编译错误**，而不会变成
  一条永远不触发的规则。
- 只有固定的方法可调用：`some`、`every`、`includes`、`indexOf`、`test`、
  `match`、`startsWith`、`endsWith`。
- 属性名 `constructor`、`__proto__`、`prototype`、`caller`、`callee`、
  `arguments` 在任何值上、以任何访问形式都被拒绝。

## 阈值

政策数字集中在一个 `thresholds` 对象里，规则以 `T.weakMark` 引用，而不是写 `60`；
建议正文用 `{{weakMark}}` 插值。所以**句子里写的数字和条件里测的数字不可能不一致**。

这不是洁癖。本工具所仿制的原始工作簿里，一条规则拿 `55` 做比较，而它自己的
文案暗示的是 `60`——两条规则对"偏弱"的定义互相矛盾，这是**验证发现的，不是读出来的**。

## 换算参数：用之前必读

规则库里的 `calibration` 是一个**未经核实的占位实现**。原始工作簿内嵌了一条
六次多项式，系数是其作者针对某一届考试成绩拟合的；那是他人的成果，此处**刻意没有复制**。

在本工具给出任何 ATAR 数字之前：

1. 对着你自己的官方换算表拟合 `coefficients`
2. 把 `calibration.verified` 设为日期
3. 从报告输出里移除那段免责声明，或者保留它并明确标注该数字仅为参考

在第 2 步完成之前，界面会在每一处标明该换算未经校准。一个未校准的换算却输出看起来
很确定的数字，是这类工具最危险的失效方式，所以这道闸门是故意留着的。

## 能力层，而不是一张专业清单

先修条件检查走的是**能力**层，而不是"专业＋要求"的对照表：

```
capabilities          mathematics     -> [ATMAA, ATMAM, ATMAS]
                      physicalScience -> [ATPHY, ATCHE]
courseExpectations    Engineering     -> expects [mathematics, physicalScience]
```

规则问的是"这位学生记录的科目是否满足该方向通常要求的准备"，而能力到科目代码的映射
只存在一处。把新确认的科目加进 `capabilities.mathematics`，所有消费它的规则**立刻**
跟着生效。

**这里原先写的是科目名**（`Mathematics`、`Physics`…），因为科目那一格是自由文本框。
那是个陷阱：匹配是精确字符串比较，学生打 `Maths`、`数学`、`Math` 都不等于
`Mathematics`，于是先修规则**静默失效**——不报错，只是从此不说话。现在科目改成下拉，
选项就是工作簿自己的科目代码，同义名一览表随之删掉：下拉里不可能出现同义名，
而一览表只会让匹配看起来比实际宽松。

代码取自工作簿 `LISTS` 表的 `SUBJECTS` 列，即原版 `Top 4 ATAR Subjects (Choose from
list)` 那张下拉：`ATACF ATBME ATCHE ATCSC ATEALD ATECO ATENG ATHBY ATMAA ATMAM
ATMAS ATPHY ATPSY`。工作簿的清单在这 13 项之后还有一段 `GTCSC … GTDRA / EPSGS`
（General 课程），**刻意没有收进来**——它们的分数不计入 ATAR。这个"没有"在做事：
最好四门合计是从记录里现算的，能打进去的 General 科目会**悄悄抬高合成分**。
下拉让这种记录压根无法表达。

这是刻意的取舍。原始工作簿的课程库里，先修要求那一列是自由文本：全表 124 行里，
只有 3 行是机器可读的形状（`English-YES Mathematics-YES Science/Other-NO`），
另有 12 行写成散文，例如 "Mathematics (Australian Higher Year 12 equivalent) and at
least one of Chemistry or Physics are formal prerequisites for the Bachelor of
Engineering"。把那种散文解析成 YES/NO 标记，等于**制造源数据并不具备的精确性**，
而这正是本项目要避免的失效方式。所以工具可靠地问出能力层面的问题，而在没有依据的地方
它说没有：

- `courseExpectations[*].namedAtar` 一律为 `null`，意思是"没有现成数字"。
  `atar-figure-not-recorded` 规则把这件事变成可见的建议，而不是让学生自行假设一个数字。
- `anyInterestExpectationGap` 只在能力**确实缺失**时才报告；未知方向不报缺口。
- `anyInterestOptionalGap` 在必需能力仍缺失时保持沉默，所以建议之间不会互相打架。

## 验证

验证脚本不在本目录内，也不随站点发布（本仓库曾因此泄露过一次脚本）。它们在本地运行，
覆盖：包结构、规则语言安全、目录一致性、内容政策、能力层逐例判定，以及
**把生产引擎本身**在 DOM 桩上跑一遍。

一个浏览器端套件曾被尝试并放弃：Playwright 用 `--remote-debugging-pipe` 启动 Chromium，
而 Chrome 自身的 mojo IPC 也需要命名管道，构建此工具的环境禁止命名管道。为了跑一个测试
去放宽沙箱不是划算的交换，所以 DOM 桩覆盖了同样的逻辑。**因此本页面的渲染从未在真实
浏览器里验证过**——如果你有浏览器，打开这两个页面把四个页签各点一遍。

## 内容政策

规则库里的每一句话都是为本模板**原创撰写**的示例文案，不是政策来源。所有数字都是占位值。
做事实性主张的规则会指出人类需要在何处核实，并在核实之前显示为"待核实"。
验证套件会在规则写出货币金额时报错，因为金额应当指向当前项目页面的链接，
而不是一个会悄悄过期的字符串。

## 来源与边界

架构研究自一份机构工作簿，并从零重新实现。具体而言：

**取用的架构**（想法，不是表达）：表单 → 规则表 → 生成报告的整体形状；
"只输出命中的内容，未命中的规则不产生任何输出"；用一次合成分换算出目标计算器所需的 ATAR。

**建过又删掉的**：原工作簿里有一张"考核追踪"表，由每条考核自身的权重推导重要度，
再用重要度×紧急度的二维矩阵给出单一建议动作。这套东西在本工具里实现过，后来整章删除——
它要求学生把每一次考核的权重和截止日期手工敲一遍，产出只是对这些刚敲进去的行做一次排序，
而这件事学校本来就在做（官方的 ACCT/EE 安排现在就挂在 Teams 上，由校方维护）。
删掉页签的同时，引擎侧的三个函数（`addAssessRow`、`summariseAssessments`、
`importanceFor`）也从打包产物里真正移除了：它们此前仍在查找 `assessRows`、`trackerSummary`
这些页面上已不存在的 id，而套件里"引擎读的每个 id 都必须在页面上存在"这一条把它抓了出来。
规则库里的 `importanceBands` 和 `matrix` 作为源表的记录保留，仍由规则套件直接断言其完整性。

**未取用**：任何建议文案、任何规则措辞、任何数值系数、任何阈值、任何大学或奖学金名单、
任何金额或网址、任何代码。原件从未在 Excel 中打开过，其宏从未被执行。其课程库只被读取
以**测量其先修数据的形态**——发现它主要是散文，这正是本模板改用能力层而不复制清单的原因。

**刻意改动**（每一条都是原设计真实存在的缺陷）：

| 原始设计 | 本实现 |
| --- | --- |
| 建议嵌在各条公式里 | 建议是规则库里的数据 |
| 无保护的精确字符串比较，打错一个字建议就静默消失 | 受控词表＋会报出问题的校验 |
| 15 张表只挂了 4 处数据验证 | 每个字段都校验，并说明原因 |
| 规则散落，无法看到全集 | 规则总览视图列出每条规则及其状态 |
| 阈值硬编码在各条规则里 | 命名阈值，条件与文案引用同一个值 |
| 课程库的先修要求是自由文本，却当作结构化数据使用 | 能力层；没有依据的数字显式暴露而非编造 |
| 规则与学生数据在同一份分发文件里 | 规则在规则库，学生数据独立 |
| 依赖 Excel 2021+ 的动态数组函数，未测旧版本 | 任意浏览器可运行，无版本依赖 |
| 拟合多项式在其拟合区间外仍被信任 | 显式标注未经核实的占位实现，拒绝显得确定 |

## 课程库

`courses.js` 里是 **54 条课程事实**，来自原工作簿的课程数据库，每条只有事实：
院校、专业、已公布的最低分、一句短要求（若原文有）、以及链接。

**没有搬的**：原表同一列里还存着各大学自己的招生与宣传段落。那是**他们的文字**，
不是关于他们的事实，所以不复制。全表 124 行里有 93 行的"其他要求"长于 160 字符、
属于这类套话。

**链接是实测的，不是照抄的。** 每条带一个状态：

| 状态 | 含义 |
| --- | --- |
| `ok` | 课程页实测可访问 |
| `blocked` | 被反爬拦截（curl 拿到 403/429）；页面存在，浏览器能打开，所以深链保留 |
| `repaired` | 深链已死，改指**已实测的院系入口**，`origin` 记录被替换的原地址 |
| `find-it` | 连入口都没测通，页面只提示"请在院校官网搜索" |

### 这里有个我犯过的错误，值得记录

第一遍我用 Python 的 `urllib` 检查链接，报了 **46 条死链**。那个结论是错的：
`urllib` 和这些站点 TLS 握手失败，而 `curl`（Windows 自带的 Schannel 栈）**全部正常**。
DNS 能解析、TCP 443 能连，我当时却把它当成了对方的坏链。

后果本来会很严重：一个把**活链接标成死链**的工具，会让学生不再相信正确的链接，
而且会让我白白丢掉仍然可用的课程数据。现在检查改用 `curl`，`check-links.py` 是可复现脚本。

同类教训在本项目里出现过第二次：改数据库前，`.gitignore` 的事也让我差点把自己的环境故障
当成对方的问题。

### 又一课：能被匹配到的数据才算数据

课程库上线后我去查它到底有没有被规则用上，发现**有两条院校的课永远不可能被匹配**，
而页面上它们看起来完全正常。

原因不是我写错了哪个表达式，是**国家的取值对不上**：

| 课程库里的值 | 表单/规则里的值 | 结果 |
| --- | --- | --- |
| `"—"`（占位符） | 无此国家 | **学生根本选不到，永远匹配不上** |
| `"UK"` | `"United Kingdom"` | 能匹配——因为引擎里写了一条 `uk ≡ united kingdom` 的等价 |

第二行值得说清楚：我一开始判定 `"UK"` 那两条（英国皇家外科医学院、华威大学）
也是死数据，**这个判断是错的**。引擎里本来就有一处针对这对写法的等价判断，
所以它们一直是可达的。真正的 bug 只有 `"—"` 那两条（新加坡国立大学）。

不过 `"UK"` 还是被改成 `"United Kingdom"` 了：同一个国家两种写法意味着**两处要同步改**，
而下面那道构建门本来就要求"课程库里的国家必须是学生能选到的"。数据用表单自己的词汇，
引擎里那条特殊判断就无事可做了。

`"—"` 的来源值得记：那是另一个**已经废弃**的生成脚本写的占位符
（`r["country"] or "—"`，源表里该格本来就是空的）。废弃脚本还活着，并且
会覆盖同一个输出文件——它一次跑出 111 行、链接状态全错的结果。所以现在：

- 国家一律写**表单自己的词汇**（`UK` → `United Kingdom`），
- 空国家从院校反推（NUS → Singapore），推不出来就**让构建失败**，
- 生成脚本里加断言：课程库里出现的每个国家，都必须是学生能选到的；
- `build.py` 里再加一道门：行数、占位符国家、不可选国家，三项任一不过就不出站。
  三条都做了反向验证——把占位符写回去、把国家改成 `Britain`、把库砍到 1 行，
  构建分别以不同理由拒绝。

这一课的一般形式是：**"数据存在"和"数据可达"是两件事**，而第二件只有跑到规则里
才看得出来。测试要问的不是"文件里有几行"，是"这些行有没有可能影响输出"。

### 已知限制：类别为空的行曾经对任何专业方向都不可见

新加坡国立大学那条课程的**类别在源表里是空的**（课程名写的是 "ANY offered"）。
匹配要求课程的类别与学生填的方向有词重叠，而空类别原本被当成"什么都不匹配"：
那条课程国家对得上，却对**任何**专业方向都不可见。

修法是**空类别 = 没有限制**，所以任何方向都能匹配它。我没有给它安一个类别——
源数据里没有，编一个就是发明事实。影响面是明确的：全库 54 条里只有这 1 条类别为空。

### 第三个错误：`—` 和半个句子

修好上面那条之后我去看实际输出，看到的是：

> 你当前 94 的水平够得上 National University of Singapore Any offered course in NUS (90)；
> **最近的一门在你之上的是 —，差 — 分。**

`{{nearestCourse}}` 没有值时，插值函数按设计填 `—`，于是"最近的一门在你之上"
这半句留在页面上，指着两个破折号。**"够得上、而且没有更高的"是常态，不是错误**，
所以正解不是补一个值，是让**这半句整体消失**。

做法是给规则文本加了可选片段标记：

```
{{#if nearestCourse}}最近的一门在你之上的是 {{nearestCourse}}，差 {{atarGap}} 分。{{/if}}
```

键为空/假时整段丢弃；落单的标记会被清掉，让写错的地方表现为"文字少了"，
而不是页面上出现花括号。

**更值得记的是测试为什么没拦住它。** 当时那条断言是"输出里出现 NUS 就算通过"，
而那段话里确实有 NUS——断言过了，文本是坏的。**断言写得比缺陷宽，就会漏。**
所以现在多了一条独立检查：把引擎产出的**每一段**都扫一遍，出现未渲染的 `{{ }}`
或悬空的 `—` 就失败。这条检查对着修好之前的引擎跑过，它会失败——不是摆设。

这三件事是同一类：**"数据在"不等于"数据可达"，"可达"不等于"输出是好的"，
"输出里有正确的词"不等于"这句话是通顺的"。**

### 一条用最低分对照成绩的规则

`atar-vs-recorded-minimum` 在学生够得上某条已记录最低分时说话，并**点名那门课**，
再点名"还差一点"的最近一门以及差多少分——只有在存在这样一门时，那半句才出现
（见上一节）。够不上任何一门时，`atar-below-all-recorded` 会说这件事——
在这里保持沉默才是最坏的选择。

专业方向的匹配是**按词**做的，不是按子串。第一版用 `indexOf` 做子串匹配，
于是 `'biomedical'.indexOf('medical')` 命中，**把"生物医学工程"当成了"医学"**，
给一个想读医学的学生推荐了工程学位。现在别名逐词比较，并且词重叠只在
**学生填的方向**与**课程名**之间成立，不再让类别参与。

### 院校改成下拉，以及它顺手解开的一串死结

原版工作簿的院校是一格自由文本，我们照做了。但那意味着：匹配靠**词重叠**，而
词重叠在这里是错的——`"Curtin University"` 和 `"University of Western Australia"`
共享单词 `university`，于是**每所院校都匹配上了每一所**。学生选 Curtin，面板报的是
UWA 的最低位；选 Monash 马来西亚校区，报的是 Sunway。**没有任何地方报错**：一份过长的
课程清单看起来仍然像一份课程清单。改成下拉（选项就是课程库自己的院校名，16 所）之后，
比较改成**精确相等**，这类错配就不可能发生了。

第二件事更要紧。**整套课程库对照此前是被一个手填数字卡住的**：

```
atarComparison(record, courses)     ← 拿 record.estimatedAtar 当 standing
  没有 standing → 返回 null
    → anyInterestHasCourses 为 false
      → 所有"对照已记录最低分"的规则一律沉默
```

也就是说：学生必须先在"当前预计 ATAR"里**猜一个数**，工具才会拿它去和课程库比。
而工具自己就能从四门成绩算出这个数。所以那一格不只是没用——它是整条对照链的闸门。

现在 `estimatedAtar` 这一格删掉了，`record.computedAtar` 由 `readRecord()` 从成绩
现算（算不出来时为 `null`，规则随之沉默，而不是拿一个不存在的数字去比）。名字也换了：
`estimatedAtar` 是"你估的"，`computedAtar` 是"我算的"，两者不该共用一个字段名。

### `atar-figure-not-recorded` 曾经在每一份报告里出现

它的条件原本是 `anyInterestMissing("i.atarRequirement")`——而 `atarRequirement`
**从来没有任何控件会去设置它**，`readRecord` 里写死为 `null`。于是：

- 这条规则在**每一份**填了志愿的报告里都触发，说"至少有一个志愿没有记录最低 ATAR，
  去课程页面查一个数字填上"——**而表单里没有能填它的地方**；
- 依赖同一个字段的 `atar-margin-thin`（就差一点够最低分）**一次也没有触发过**。

一条催读者去做一件做不到的事的规则，和一条永远不会出现的建议，是同一个毛病的两面。
现在这个字段整体删除了（连同 `anyInterestMissing` 与 `belowStatedMinimum` 两个只为它
存在的 helper），`atar-margin-thin` 改为向课程库提问：**你上方最近的一条记录最低分，
是不是在 2 分以内**（新 helper `nearestAboveWithin`）。而 `atar-figure-not-recorded`
保留了 id，含义换成它真正能说的事：**这份库里没有你填的那个组合**——此时无法对照，
读者需要自己去看课程页面。这种情况现在由 `anyInterestUnmatched` 逐条判定，因为
`anyInterestHasCourses` 是跨志愿取并集的：一个匹配不上的志愿会**悄悄**从对照里消失，
学生看到的对照覆盖的志愿比他填的少，而没有任何提示。

### 顺手补上的一个测试盲区

`verify-dom` 之前**没有加载 `courses.js`**。它测的是一个课程库为空的引擎——在那个引擎里，
每一条依赖课程库的规则都是哑的，而**坏掉的规则和正常的规则看起来一模一样**。
verify-rules 的镜像里早就写着这条警告（"A harness that skips it makes every
library-driven rule look silent"），只是这一个 harness 自己没照做。现在它在引擎之前
按页面同样的顺序加载课程库，并把行数打出来。

## 已知缺口

- **本页面未在真实浏览器中渲染验证过**（见"验证"）。
- `calibration` 未经校准。
- 规则总览里标为"待核实"的规则，含有尚未对照当前来源确认的事实性表述。
- `courseExpectations[*].namedAtar` 全部为 `null`，所以工具能拿你记录的数字作比较，
  但自己不提供任何数字。
- 能力层现在按工作簿的科目代码索引，但 `mathematics` 把 `ATMAA`（Applications）与
  `ATMAM`/`ATMAS`（Methods / Specialist）算作同一项。WACE 把这几个当作不同深度，
  要求 Methods 的工程专业并不被 Applications 满足。工作簿自己的课程库也没记这个区别，
  所以在这里拆开等于**发明一条它从未记录的要求**。这是能力层目前最粗的一处。
- **实测删掉的字段**：第一轮删掉 `学号`、`Year 11 学校`、`Year 11 成绩`、`往期成绩`
  以及 `往期班次`。前四个经探针实测**没有任何规则读取**（探针在真实求值时记录字段访问；
  静态扫描看不穿 `anyInterest("i.country", …)` 这类把字段名当字符串参数的写法）。
  删掉它们的同时，`perf-prior-intake-underperformed` 规则也一并删除——它依赖
  `record.priorResults`，字段没了这条规则就永远无法触发，而一条谁都无法满足的规则
  比没有规则更糟：它是永远不会出现的建议。

### 停用的规则：字段没了，规则不能装作还在读

第二轮删掉身份区块（姓名、学号、Year 11 学校、英语是否母语、入学批次）之后，
有两条规则**读的字段全没了，条件因此恒为真**：

| 规则 | 原来读的 | 后果 |
| --- | --- | --- |
| `form-incomplete` | `fullName`、`year11School` | 每一份报告都印上"这份报告只是暂定的" |
| `funding-not-recorded` | `fundingSecured` | 每一份报告都说"还没有记录学费来源" |
| `perf-high-at-load` | `s.level`（读了错的字段） | 恒不成立，从未触发；改对字段后又恒成立 |

前两条是"每一份报告都带着一句假话"，第三条是它的镜像：一句**永远不会出现**的话。
三种状态都是同一个毛病的不同侧面——**字段没了，规则不能装作还在读它**。

这不是"建议稍微不准"，是**每一份报告都带着一句不成立的话**——而且是那种读者会当成
真实结论的话。`form-incomplete` 更尴尬：它唯一还成立的子句（科目表为空）本来就是一条
硬校验错误，有它的时候根本生成不出报告。

处理方式是把它们标成 `enabled: false`，**而不是删掉**。这个文件开头的约定就是这么写的：
停用的规则留在目录里，规则总览会把它列出来并注明"已停用"。删掉的话，决定就从记录里消失了，
下一次有人问"为什么没有这条建议"就查不到答案。目录仍是 30 条，其中 **3 条停用**。

另外两条规则只是**少了一个子句**，去掉后依然成立，于是保留：

- `course-undecided` 去掉 `record.stillDeciding === true`，剩下"没有意向行"和"方向选了 Undecided"。
- `lang-english-test` 去掉 `record.englishFirstLanguage !== true`。它的建议原文是
  "如果英语不是你的母语……"，而本工具已经不再收集这个信息，所以**文案也改了**：
  改成陈述"这些目的地以英语授课，当地多数院校会要求英语能力证明"。
  不能保留一句依赖已删字段的假设，哪怕它听起来更贴心。

### 第三条停用的规则：它读错了字段，而且两种状态都是错的

`perf-high-at-load`（"你记录的每一门都是最高阶科目"）判的是
`countSubject("AT") === record.subjects.length`，而 `countSubject` 当时读的是
`s.level`——科目行上那个"班次"下拉。工作簿里 `AT…` 是**科目代码**的前缀
（`ATMAM`、`ATPHY`…，代表计入 ATAR 的课程），班次下拉里则是
`Year 11 / September intake / January intake`。没有一个以 `AT` 开头，于是
`countSubject("AT")` 恒为 0，而另一个条件要求科目数 ≥ 4 —— **这条规则从写下来那天起
一次也没有触发过。** 套件里"Year 11 科目不应触发高阶课程规则"那条断言一直在通过：
它通过是因为什么都触发不了。**断言比缺陷宽，就会漏。**

把字段改对之后，它撞上第二种错：科目下拉只提供 ATAR 课程，于是
`countSubject("AT") === 科目数` 对**每一份**完整记录都成立。这时若启用它，
每一份报告都会印上"你所有科目都是最高阶"——和 `funding-not-recorded` 同一类：
把常量当建议。这个区分已经由表单本身保证（General 课程打不进来），所以这条规则
**留在目录里、标为停用**，由规则总览记录这个决定。

### 删掉的两列：班次、已考权重

两列都不是凭空来的，但都以错误的方式留在了表单上。

| 列 | 来源 | 为什么删 |
| --- | --- | --- |
| 班次 | 工作簿里 intake 是**学生一级**的勾选框（"If you were part of the Sept/ Head Start intakes, please check this box"） | 删身份区块时，`previousIntake` 的**词表**没跟着删，飘到了科目行上，变成问一个已不存在的问题；还顺手弄死了上面那条规则。工作簿的科目表里没有这一列 |
| 已考权重 | 工作簿 `TARGET CALCULATOR` 的 `Total (%) already assessed by school` | 我们只搬了输入，没搬算法。那一列的用处是喂给旁边的 `Marks required for remaining assessment(s)` 和 `Maximum possible mark`，以及下方的 `Focused weightage calculator`（`coverage % × current marks % = banked`）。一条计算都没搬，于是它成了一个只进不出的输入框——读者看不懂是必然的 |

已考权重**将来可能回来**：等要做"已经锁定多少分 / 剩下的考核要考多少才够目标"时，
它是那套算法的输入。届时一并补上，而不是单独把这一格放回去。

### 让这类缺陷下次自己暴露

上面这个缺陷是**重构带出来的**，而且进了打包产物。为此加了一条不变量检查，跑在每次套件里：

> 把引擎自己的 `readRecord()` 返回的字段集合，与**每条启用规则**在 `when` 里点名的
> `record.<字段>` 逐一对照，任何一边没有的字段即失败。

停用的规则豁免——它们正是因为字段没了才停用（这一点由另一条检查保证：停用的规则
永不触发，且必须带停用原因）。这条检查本身也做过反证：往一条启用规则里注入
`record.fullName`，套件确实失败；不是一条永远绿的摆设。

### 规则总览曾经是空的

切到「规则总览」页签，看到的是一张空表和一个空的统计行——**只有先按下「生成建议报告」
才会被填充**，因为渲染那段代码写在生成按钮的处理函数里。读者看到空格子的第一反应是
"这个功能坏了"，而不是"我还没生成报告"。

现在渲染拆成了一个独立函数 `renderCoverage(results)`：进入页面时按当前（空）表单画一次，
每次切到该页签时再按当前表单重画。它也不再依赖 `report` 对象存在——"命中几条"是从本次
求值结果里数出来的。套件里那条断言也是照着这个缺陷写的：先把表格清空、再点页签，
表格必须重新填满。

### 其他已知缺口

- 存储只有浏览器 `localStorage`，**按语言分别保存**（键为 `advising-workbook-record-v2-<语言>`）。
  没有多顾问同步、没有审计日志、没有单个学生的文件格式。
  键里的 `v2` 是刻意的：这一版记录形状变了（少六个字段），沿用旧键会把一份半截的草稿
  悄悄读回来，新键则让它干脆找不到——这是诚实的失败方式。
- 报告可导出为 Markdown，或经浏览器打印为 PDF；没有 `.docx` 输出。
- 院校下拉只能给出**课程库里有的**16 所。库里没有的院校填不进去——这比让你打一个
  永远匹配不上的名字要好，但如果你要申请库外的学校，它就在这里帮不上忙。
- 选课表里的科目下拉只收 ATAR 科目（`AT…`）。General 课程的分数不计入 ATAR，
  所以收进来只会污染最好四门合计——但也意味着**工具看不到你的 General 科目**，
  先修检查不会把它们算进去。
